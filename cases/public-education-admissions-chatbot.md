# 공개 교육기관 입학상담 챗봇 + SAPiE 멀티테넌트 RAG 백엔드

> 공개 케이스. 정량 성과 수치는 미보유 — 이 페이지는 수치를 주장하지 않습니다.

## 검증 및 공개 상태

- 마지막 문서 검토: 2026-06-28.
- 공개 표시명: `공개 교육기관`. 승인 메타데이터가 명시적으로 갱신되기 전에는 조직 실명을 표시하지 않습니다.
- 공개적으로 독립 검증 가능한 범위는 운영 endpoint의 도달성과 이 문서에 연결된 공개 surface입니다. 소스·역할·운영 세부는 PRIVATE SSOT의 승인된 요약에 근거하며 공개 코드로 재현할 수 없습니다.
- 공개 저장소의 파일명과 링크 텍스트는 설명형 표현만 사용합니다. 운영 URL은 익명화 정책에 따라 이 문서에 직접 기재하지 않으며, 검증이 필요한 자리에서 승인된 범위로 별도 공유합니다.

## 한 줄 요약

공개 교육기관 입학상담 챗봇(카카오 i 채널)과 사내 SAPiE 멀티테넌트 챗봇 플랫폼의 **FastAPI 백엔드 전체를 단독으로 설계·구현·운영**한 실제 대학 운영 RAG 서비스입니다 — 트랙별로 다른 임베딩/벡터스토어 전략, HWP까지 포함한 테이블 인지 문서 파이프라인, SSE 스트리밍·비용 추적 같은 운영 디테일을 갖췄습니다.

## 문제

- 대학 입학상담은 질문이 입시 연도(2025/2026)에 강하게 묶여 있고, 모집요강·전형 일정 같은 근거 문서가 주기적으로 갱신됩니다 — 일반 챗봇이 아니라 **연도별 도메인 지식이 정확히 주입되는 RAG**가 필요했습니다.
- 채널이 카카오 i라서, 카카오 챗봇의 응답 시간 제약 안에서 LLM 응답을 처리하는 **콜백 기반 비동기 응답**이 필요했습니다.
- 동시에 사내 SAPiE 트랙은 "사용자가 자기 문서를 올리면 자기만의 챗봇이 되는" **멀티테넌트** 요구 — 테넌트별 지식 격리와 영속화가 핵심 제약이었습니다.

## 이중 RAG 트랙 — 제약이 다르면 전략이 달라진다

| | 공개 교육기관 트랙 (단일 도메인) | SAPiE 트랙 (멀티테넌트) |
| --- | --- | --- |
| 임베딩 | VoyageAI `voyage-3-large` | Bedrock Titan |
| 벡터스토어 | FAISS + MMR 검색(k=3, fetch_k=20) — 검색 다양성 | **사용자별 FAISS** + S3 영속화·온디맨드 다운로드 — 테넌트 격리·무상태 인스턴스 |
| 채널 | 카카오 i (콜백 비동기 응답) | 웹 클라이언트 SSE 스트리밍 |

LLM은 두 트랙 공통: Bedrock Claude Sonnet 4(inference profile) 메인 + Haiku 3.5 폴백/샘플링. 대화 상태는 MongoDB 이력(최근 10턴)을 커스텀 chat history 클래스로 직접 제어하고, 2025→2026 입시 연도 전환은 코드 수정 없이 Jinja2 도메인 프롬프트 갱신으로 흡수합니다.

## 문서 파이프라인 — 표 구조를 잃지 않는 것이 검색 품질의 전제

업로드(10MB 제한) → **HWP**/DOCX/XLSX/PPT → PDF 변환 → pdfplumber/pymupdf4llm로 테이블 유무에 따라 HTML/Markdown 분기 추출 → RecursiveCharacterTextSplitter(chunk 6000/overlap 250) → 임베딩 → FAISS 생성 → S3 업로드.

입시 요강은 모집 인원·전형 일정·등급 기준이 전부 표 안에 있어서 표가 깨지면 검색이 맞아도 답이 틀립니다 — 추출 단계의 분기 설계와, 한국 공공·교육 도메인의 현실 포맷인 HWP를 1급 입력으로 받은 것이 이 파이프라인의 도메인 적합성입니다.

## 운영 디테일 — PoC가 아니라 운영 서비스라서 들어간 것들

- **SSE 개행 보존**: SSE는 규격상 개행을 이벤트 구분자로 쓰기 때문에 답변 내 개행이 깨지는 문제 → 커스텀 딜리미터로 개행을 보존하는 스트리밍 프로토콜을 직접 정의.
- **동시성 안전장치**: 세마포어로 동시 스트리밍 상한 제한(`STREAM_MAX_CONCURRENCY=2`) — 소형 인스턴스에서 스트리밍 폭주로 서비스 전체가 죽는 것을 방지.
- **비용 가시성**: 채널별(교육기관/카카오/웹) 토큰 비용 추적 콜백 3종 + 사용자·월별 롤업 — "누가 얼마 쓰는지"를 설계 단계부터 계측.
- **배포**: AWS CodeBuild/CodeDeploy → EC2, systemd 상시 구동 — 벡터DB 데이터 업데이트 이력이 남아 있는 운영 사이클.

## 실서비스

**실제 운영 중인 산출물** — 공개 교육기관 입학상담 챗봇

실제 대학 운영 서비스로 배포·유지보수 중이며, 일회성 PoC가 아닌 운영 사이클의 증거(데이터 업데이트 이력 포함)가 남아 있습니다.

## 라이브 동작 증거 (2026-06-18 캡처)

운영 서비스에서 직접 질의해 RAG 동작을 풀페이지 5종으로 캡처했습니다 (개인정보 없는 합성 질문). 단순 검색 성공뿐 아니라 운영 안전성(환각 억제·도메인 가드레일)까지 라이브에서 보여줍니다.

| 캡처 | 질문 | 동작 (보여주는 것) |
| --- | --- | --- |
| qa1 | 수시 2차 원서 접수 기간? | 모집요강에서 정확한 날짜를 검색·인용 |
| qa2 | 자유전공학과 정원·수업연한? | 정원·수업연한·신설연도·위치·학과번호까지 검색 |
| qa3 | 교육기관 위치? | 주소·입학홍보처 연락처 검색 |
| qa4 | 신입생 장학금 제도? | 문서에 근거가 없으면 환각 없이 "확인 불가" + 담당부서 안내 (RAG 정직성) |
| qa5 | "오늘 점심 메뉴 추천?" | "답변할 수 없는 질문" + 입학상담만 안내 (도메인 가드레일) |

- qa1~qa3은 **정확한 검색**, qa4는 **환각 억제**(근거 없는 답을 지어내지 않음), qa5는 **도메인 가드레일**(입학상담 밖 질문 차단)을 보여줍니다.
- **모델 표기 주의(정직)**: 운영 UI 인사말 카피는 "Claude 3.5 기반"으로 남아 있으나, 코드 기준 메인 추론 모델은 **Claude Sonnet 4**(inference profile) + 폴백 Haiku 3.5입니다 — 인사말 카피가 모델 업그레이드 시점에 갱신되지 않은 것입니다.

## 정직한 한계

- 상담 건수·응답 정확도 같은 **정량 성과 지표는 미보유** — 운영 사실과 코드 수준 증거까지만 주장합니다.
- RAG 검색 품질에 대한 체계적 평가(골든셋, 회귀 평가)는 구축되어 있지 않습니다.
- 소스는 비공개 — 외부에서 검증 가능한 것은 운영 중인 서비스 자체입니다.

## 무엇을 증명하는가

- RAG 시스템을 PoC가 아닌 **실제 운영 서비스**로 단독 설계·구현·운영한 풀사이클 역량.
- 채널 제약(카카오 콜백)·프로토콜 제약(SSE 개행)·도메인 제약(HWP·표 중심 문서)을 각각의 층위에서 푸는 실전 엔지니어링.
- 멀티테넌트 격리·비용 계측·동시성 상한 같은 운영 관점을 설계 단계부터 넣는 습관.
