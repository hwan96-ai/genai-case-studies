# 한국어 TTS 평가 기준 설계 — 스마트홈 월패드 음성 안내 모델 선정

> 공개 케이스. 고객사명은 익명. 모델명·수치는 본인이 직접 측정한 벤치마크 산출물 기준.

## 한 줄 요약

스마트홈 월패드 음성 안내에 쓸 한국어 TTS를 골라달라는 고객 요청에서, **"어떤 모델이 좋은가" 대신 "무엇이 좋다는 기준인가"를 먼저 설계**해 6개 모델을 실측 비교했고, 이 평가가 **실제 고객 계약으로 이어져 2026년 3월 완료**됐습니다.

## 문제

월패드 음성 안내는 일반 TTS 데모와 요구가 다릅니다. 실시간 응답성, 임베디드급 리소스 제약, 오프라인 동작 가능성, 상업 라이선스 명확성, 그리고 "22도", "약풍 가동"처럼 숫자·기술 용어가 섞인 한국어 문장의 발음 정확도까지 — 단순 음질 비교로는 의사결정이 되지 않았습니다.

## 접근: 기준을 먼저, 측정은 그 다음

측정 전에 합격선을 SPEC으로 정의했습니다:

| 평가 축 | 기준 | 도출 근거 |
| --- | --- | --- |
| 응답 속도 | RTF(실시간 계수) < 0.5 | 안내 음성의 실시간성 요구를 정량화 |
| 메모리 | < 1GB 선호 | Raspberry Pi 4 / Jetson Nano급 탑재 가능성 |
| 한국어 발음 | 숫자·기술용어·운율 정확도 | 안내 문장 특성 (시나리오 문장으로 검증) |
| 라이선스 | 상업 사용 명확성 (MIT/Apache 우선) | 제품 탑재 전제 |
| 운영 | 오프라인 가능, 설치 난이도, 비용 | 인터넷 단절 가능 환경 |

그리고 설치 방식이 전부 다른 6개 엔진(API/pip/HuggingFace/공식 라이브러리)을 동일 조건에서 비교할 수 있도록 **어댑터 패턴 벤치마크 하네스**를 약 2일 만에 구축했습니다 — 모델 로드와 추론 측정을 분리하고, 측정 전후 gc/CUDA 동기화로 노이즈를 통제하고, 문장×반복 매트릭스를 자동 실행해 CSV로 집계합니다.

## 결과 (2025-10 실측: CSV 130행, 생성 음성 157개)

| 모델 | RTF (실측) | 판정 |
| --- | --- | --- |
| **MeloTTS-Korean** | **0.063** | **즉시 도입 1순위** — 한국어 전용, MIT 라이선스, 완전 오프라인, CPU로 실시간의 약 16배 속도 |
| **CosyVoice-300M-SFT** | 0.28 | **품질 우선 대안** — 한국어 전용 화자, 설치 복잡·숫자 영어 읽기 이슈 |
| gTTS | 0.13 | 프로토타입 전용 — 비공식 API라 상업 사용 리스크 |
| Zonos-v0.1 | 2.11 (첫 호출 29s) | 탈락 — 한국어 학습 비중 미미, GPU 3.6GB |
| Kokoro-82M | (생성 성공) | 탈락 — 한국어 미지원, 영어 음소 폴백: "성공률 5/5인데 발음 불가" |
| Coqui XTTS-v2 | — | 용도 불일치 (zero-shot 복제 전용) |

성능을 넘어 라이선스·운영 비용·임베디드 적합성까지 포함한 의사결정 매트릭스로 정리해, 추천뿐 아니라 **탈락 근거까지 데이터로** 제시했습니다.

## 비즈니스 결과

이 평가 기준 설계와 실측 결과가 해당 고객과의 **실제 계약으로 이어졌고, 계약은 2026년 3월에 종료(완료)**됐습니다. (고객사명은 비공개)

## 정직한 한계

- 품질 평가는 본인 청취 기준(주관) — MOS 패널·ASR 역전사 같은 객관 지표는 다음 단계 과제.
- CSV 실측은 3개 모델 기준이며 일부 수치는 문서 기록치. 단일 머신·이틀간의 스냅샷.
- Zonos 화자 고정 시드 스윕 실험은 0/10 실패 — 안 된 것도 그대로 기록했습니다.

## 무엇을 증명하는가

- 사용 맥락을 측정 가능한 기준으로 번역하는 평가 설계 역량.
- 이질적인 후보들을 공정 비교하는 하네스 구축 역량 (어댑터 패턴, 측정 노이즈 통제).
- 기술 평가를 비즈니스 의사결정(계약)으로 연결한 실적.
