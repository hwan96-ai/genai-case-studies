# Sapie Reco — LLM 기반 이커머스 배치 상품 추천 엔진 델리버리 (A07)

> 공개 케이스. 정량 성과 수치는 미보유 — 이 페이지는 수치를 주장하지 않습니다.

## 검증 상태

- 마지막 문서 검토: 2026-06-28.
- 공개적으로 독립 검증 가능한 범위: 출시 사실과 연결된 공개 근거.
- 구조·역할·운영 세부: PRIVATE SSOT의 승인된 요약을 바탕으로 하며 공개 코드로 재현할 수 없습니다.
- 공개 근거, 역할 경계, 승인 상태가 바뀌면 이 문서를 다시 검토합니다. 그전까지 구현 세부는 검증 가능한 공개 사실이 아니라 출처가 제한된 설명으로 읽습니다.

## 한 줄 요약

idus(backpackr) 이커머스를 대상으로 한 **LLM 기반 배치 상품 추천 엔진 "Sapie Reco"의 델리버리를 총괄**했습니다 — Airflow + AWS Batch 위에서 Claude 모델을 역할별로 계층화해 약 18,000개 상품의 테마 생성·추천 랭킹을 야간 배치로 수행하는 시스템으로, **실제 상용 서비스로 공개 출시**되었습니다.

## 내 역할 (정직하게)

- **PM / 델리버리 총괄** — 고객(idus)과 매일 데일리 스크럼·면담으로 니즈를 반영하며 프로젝트를 디벨롭하고, LLM 기반 추천 알고리즘과 시즌별 테마 생성 방향을 제안하며 팀원에게 작업을 분배했습니다.
- **직접 구현한 부분** — 테마 생성·추천 양쪽 파이프라인에 들어가는 **RAG 코어**를 직접 개발했고, 고객에게 전달한 **콜드유저(신규 사용자) 선물 추천 챗봇 PoC**와 **판매자 전용 챗봇 PoC**를 직접 구축했습니다.
- **역할 경계** — 배치 추천 엔진 구현 커밋의 다수는 동료 엔지니어의 작업입니다. 따라서 "엔진 전체를 솔로 구현했다"고 주장하지 않으며, 기여를 총괄(PM/델리버리) + 위의 특정 직접 구현(RAG 코어·PoC 챗봇 2종)으로 한정합니다.

## 문제

핸드메이드 이커머스의 추천은 "키워드 → 테마 → 상품 랭킹"이라는 의미 단계가 필요합니다. 단순 협업 필터링으로는 "어버이날 선물" 같은 시즌성이나 "집들이 답례품" 같은 용도 기반 큐레이션이 어렵습니다. LLM을 추천에 쓰되 약 18,000개 상품을 매일 처리해야 하므로, **비용·시간·실패 복원력이 전부 설계 대상**이었습니다 — 모든 호출을 최상위 모델로 처리하면 비용이 폭증하고, 장시간 배치는 부분 실패가 기본 전제입니다.

## 접근

- **오케스트레이션과 연산의 분리**: Airflow 2.10.5(CeleryExecutor) DAG는 스케줄·의존성·재시도만 관장하고, 무거운 연산은 AWS Batch 잡으로 위임. 인프라는 AWS CDK/CloudFormation IaC로 코드 관리.
- **두 개의 DAG**: `reco-theme`(키워드→테마 생성), `reco-pick`(occasion 분류→테마 분류→추천 랭킹, 장기 배치 특성을 반영한 48시간 타임아웃).
- **LLM 구성 (AWS Bedrock)**: 테마 생성은 Claude 3.5 Sonnet(품질), 대량 분류·랭킹은 Claude 3.5 Haiku(비용), 임베딩은 Amazon Titan, 벡터스토어는 ChromaDB(cosine, HNSW M=64).

## 핵심 아키텍처 결정

| 결정 | 내용 |

| 모델 비용 계층화 | 호출량이 많은 분류·랭킹 단계에 저비용 Haiku, 품질이 필요한 테마 생성에 Sonnet — 단가 차이(입력·출력 각 3배)와 호출량 분포를 근거로 한 배치 |

| 실패 복원력 | 재시도 3회 + 지수 백오프, LLM 랭킹 실패 시 CTA(클릭률) 정렬 폴백 — 48시간 배치에서 단일 호출 실패가 전체를 죽이지 않는 우아한 강등 |
| 계층적 재랭킹 | 50개 초과 배치는 서브배치 상위 20%만 모아 최종 재랭킹 — LLM 컨텍스트 한계를 토너먼트 구조로 우회 |
| 프롬프트 기준 명문화 | 68줄 시스템 프롬프트에 좋은/나쁜 예시와 시즌성·용도 분류 기준을 명시 — LLM 출력 일관성 확보 |
| 실험 가능 구조 | 추천 결과의 AB 테스트 그룹 라우팅 지원 |

## 정직한 한계

- 전환율·CTR 개선 등 **정량 성과 지표는 비공개이거나 미보유** — 이 페이지에서 성과 수치를 주장하지 않습니다.
- **본인 역할은 델리버리 리드·총괄 참여이며, RAG 코어와 PoC 챗봇 2종은 직접 구현**(위 "내 역할" 참조) — 배치 추천 엔진 구현 커밋의 다수는 동료 엔지니어의 작업이라 엔진 전체의 단독 구현은 주장하지 않습니다. 이 케이스는 시스템 구조와 엔지니어링 결정을 총괄 관점에서 설명하고, 직접 구현분을 정직하게 구분할 수 있다는 증거입니다.
- 소스는 비공개라 외부 검증 가능한 공개 코드는 없습니다 — 출시 사실의 공개 근거는 보도자료입니다.

## 무엇을 증명하는가

- LLM을 대규모 배치 워크로드에 넣을 때의 비용·실패·운영 설계를 결정 단위로 설명하는 역량.
- 델리버리 리드로서 아키텍처 결정 구조를 책임지고 방어하는 역량 — 역할 경계를 정직하게 긋는 것 포함.
